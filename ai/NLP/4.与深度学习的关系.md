# 🔗 NLP 与深度学习的关系

现代 NLP 几乎全部基于深度学习，尤其是 **Transformer** 架构。本文梳理"文本如何被深度学习处理"的完整链路，以及预训练 + 微调范式。

---

## 🏗️ 一、文本进入神经网络的流程

```
原始文本
  → Tokenizer（分词）→ 词元序列
  → Embedding（词向量）→ 稠密向量
  → Transformer 编码器/解码器
  → 下游任务头（分类/生成/标注）
```

### 1. Tokenizer（分词）

把文本切成模型能处理的最小单元：

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")
tokens = tokenizer("你好，世界")
# {'input_ids': [101, 872, 1962, 102], 'token_type_ids': [...], 'attention_mask': [...]}
```

### 2. Embedding（词向量）

每个词元映射为一个向量，语义相近的词向量距离近。

### 3. Transformer 编码器/解码器

- **编码器**：双向理解整个序列（BERT 风格）
- **解码器**：从左到右生成（GPT 风格）

---

## 🧪 二、预训练 + 微调范式

这是过去几年 NLP 的核心范式，把"通用语言知识"和"具体任务"分离。

### 阶段 1：预训练（Pretraining）

在海量无标注语料上自监督学习，让模型掌握通用语言知识。

| 预训练任务 | 说明 | 代表模型 |
| --- | --- | --- |
| **掩码语言模型（MLM）** | 盖住部分词，让模型预测 | BERT |
| **自回归语言模型** | 预测下一个词 | GPT |
| **对比学习** | 让相似文本表示更近 | SimCSE |

### 阶段 2：微调（Fine-tuning）

用少量任务标注数据，让预训练模型适配具体任务。

```python
# 情感分析微调
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(
    "bert-base-chinese", num_labels=2
)
# 在标注数据上训练几个 epoch 即可
```

### 阶段 3：大模型时代的演进

微调不再是唯一出路，出现了更高效的适配方式：

| 方式 | 说明 | 成本 |
| --- | --- | --- |
| **Prompt 工程** | 用提示词引导，不训练 | 零 |
| **In-context Learning** | 给示例让模型模仿 | 零 |
| **LoRA / PEFT** | 只训练少量参数 | 低 |
| **全量微调** | 训练全部参数 | 高 |
| **RLHF** | 人类反馈对齐 | 高 |

---

## 🔧 三、任务头（Task Head）

预训练模型提供通用表示，具体任务靠不同的"头"：

| 任务 | 输出结构 | 常用头 |
| --- | --- | --- |
| 文本分类 | 一个标签 | `CLS` 向量 + 线性层 |
| 序列标注 | 每词一个标签 | 每个 token 向量 + 线性层 |
| 文本生成 | 序列 | 解码器自回归输出 |
| 句对匹配 | 相似度 | 两个句子的向量拼接 + 线性层 |

```python
# BERT 分类头：取 [CLS] token 的表示做分类
cls_repr = outputs.pooler_output   # 形状 (batch, hidden)
logits = classifier(cls_repr)      # 线性层 → 类别得分
```

## 🎯 小结

- 文本处理链路：Tokenizer → Embedding → Transformer → 任务头
- 预训练学通用语言，微调适配具体任务
- 大模型时代转向 Prompt / LoRA 等轻量适配方式
